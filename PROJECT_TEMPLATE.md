# Project README template (every project folder follows this)

1. **Title line:** folder name + the one idea as a plain sentence.
2. **The idea in simple words** (5–10 lines, no jargon without a gloss).
   This section is the draft skeleton for the newsletter edition's Deep
   dive: write it like the edition, not like documentation.
3. **Run it**: the exact commands, copy-paste ready.
4. **What to notice in the output**: 2–4 bullets naming the specific
   behavior the reader should see. The edition quotes this.
5. **Files**: one line per file.
6. **Try this**: 1–2 exercises, the first one always demonstrates the
   failure the project prevents.
7. **Newsletter**: edition number and title that explain this project.

Rules: 100–300 lines of code, plain-language comments, pinned
requirements, sample output committed as `output.txt`, no API key needed
unless unavoidable (prefer Ollama / FAISS / sqlite local paths).
